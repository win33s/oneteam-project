# 설계 (2026-10-01)

기획(`기획.md`)을 데모로 구현한 구조와 결정 사항입니다.

## 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 프론트엔드 | React + Vite | 팀원이 화면 단위로 나눠 작업하기 쉬움 |
| 서버 | Node(Express), JSON 파일 저장 | 설치할 DB 없이 바로 실행 |
| 에이전트 판단 | 규칙 기반이 기본, Claude API는 선택 연동 | 키 없이도 데모가 항상 같은 결과로 동작 |
| 사내 시스템 | ERP·캘린더·조직도·메일·후기 폼을 모두 가상으로 구현 | 실제 사내 시스템에는 접근할 수 없음 |
| 데이터 | 부서·인물·장소·경비 모두 지어낸 값 | 실제 업체에 가짜 후기가 붙지 않도록 함 |

## 에이전트 동작

### 1. ERP 크롤링 (`crawler.js`, `records.js`)

- API가 아니라 ERP **화면(HTML)** 을 읽는다. 목록 페이지를 넘기며 전표번호를 모으고, 계정코드가 회의비(53210) 또는 복리후생비-조직활성화(52140)인 새 전표만 상세 화면을 열어 필드를 읽는다. 사무용품비·출장비 등은 제외한다.
- 읽는 필드: 전표번호, 사용일, 부서, 기안자, 계정명·계정코드, 예산구분(팀장 배정 예산 / 부서 공통 예산), 제목, 거래처, 품목, 용도, 구입·소비 내역, 인원, 금액.
- 서버 최초 실행 시 전체 이력을 한 번 수집해 부서별 활동 기록을 만든다. 담당자가 입사하기 전 기록도 여기서 생긴다.
- 이후 10초마다 새 전표를 확인한다. 새 전표가 나오면 활동 기록을 만들고, 확정된 기획과 장소·날짜가 맞으면 연결하고, 담당자에게 기록 업데이트 메일을, 참석자에게 후기 폼 메일을 보낸다.
- 처음 보는 거래처는 품목·제목 키워드로 유형을 추정해 장소 DB에 새로 등록한다.

### 2. 날짜 추천 (`scheduler.js`)

- 조직도에서 고른 부서원의 캘린더(휴가·출장·교육·야간 근무)와 부서 과제 일정을 본다.
- 점수 = 참석 가능 비율 + 요일 가산점 − 과제 일정 근접 감점 − 팀장 불참 감점. 주말과 공휴일은 제외한다.
- 상위 6개를 근거(누가 왜 안 되는지, 어느 과제 일정과 가까운지)와 함께 보여 준다.

### 3. 날짜 투표

- 후보를 2개 이상 고르면 선택한 부서원 전원에게 투표 메일을 보낸다.
- 담당자 화면은 2.5초마다 결과를 다시 불러와 실시간으로 보여 준다.

### 4. 장소·활동 추천 (`recommender.js`)

점수에 들어가는 근거:

- 타부서 후기 평점
- 시기 적합성 (그 계절에 실제로 다녀온 곳인지)
- 우리 부서 방문 횟수 (많이 갔으면 감점, 처음이면 가산점)
- 1인당 평균 경비와 예산
- 개인 프로필 (채식, 해산물·매운 음식 불가, 음주 여부, 선호 유형)
- 수용 인원

각 추천에는 타부서 경비 기록(부서, 사용일, 금액, 계정, 예산구분), 후기, 담당자 팁, 사내 블로그 게시글 수를 근거로 붙인다.

### 5. Claude API 선택 연동 (`llm.js`)

`ANTHROPIC_API_KEY`가 있을 때만 켜진다. 없으면 규칙 기반 결과를 그대로 쓴다.

- 첫 화면 자유 입력을 기획 조건(유형, 예산, 기간)으로 해석
- 추천 결과에 대한 3~4문장 조언 작성 (주어진 근거 데이터만 사용)

## 실제 사내 적용 시 바꿀 부분

| 데모 | 실제 |
|---|---|
| `erp.js` Mock 화면 | 사내 ERP 화면 또는 API. `crawler.js`의 선택자와 로그인 처리만 교체 |
| `seed.js`의 캘린더·조직도 | 사내 캘린더·조직도 연동 |
| `mailer.js` 데모 메일함 | 사내 메일 발송 |
| `/review/:id` 데모 폼 | 네이버 폼 생성·응답 수집 |
| 블로그 게시글 수 | 사내 블로그 단체 사진 수집 |
| `data/db.json` | 사내 DB |
