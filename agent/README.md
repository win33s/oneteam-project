# HBM — Happy Bonding Memory (데모)

부서의 조직문화활동을 처음 맡은 기획 담당자를 위한 에이전트와 웹사이트입니다. Bonding은 유대감을 쌓는다는 뜻을, Memory는 활동의 기억과 방문·기획 이력을 남긴다는 뜻을 함께 담았습니다. 날짜 잡기, 장소 추천, 예약, 안내, 경비 기록 수집, 후기 수집까지 한 흐름으로 이어집니다.

ERP·캘린더·조직도·메일은 모두 **가상(Mock)** 이며, 부서·인물·장소·경비 데이터도 모두 지어낸 값입니다.

## 실행

```bash
npm install
npm start
```

브라우저에서 http://localhost:4000 을 엽니다.

개발할 때는 `npm run dev`를 쓰고 http://localhost:5173 을 엽니다 (화면 수정이 바로 반영됨).

| 명령 | 설명 |
|---|---|
| `npm start` | 화면을 빌드하고 서버 실행 (포트 4000) |
| `npm run dev` | 서버(4000)와 Vite 개발 서버(5173) 동시 실행 |
| `npm run reset` | 데모 데이터 초기화. 서버를 다시 시작하면 새로 생성 |

### Claude API 연동 (선택)

환경변수 `ANTHROPIC_API_KEY`를 설정하고 서버를 시작하면, 첫 화면의 문장 해석과 추천 조언을 Claude가 작성합니다. 없으면 규칙 기반으로 동작합니다.

## Vercel 배포

Vercel에서는 서버가 요청 때만 잠깐 실행되므로, 데이터를 파일 대신 Upstash Redis에 저장합니다.

1. Vercel 프로젝트 → Settings → Build and Deployment → **Root Directory**를 `agent`로 설정합니다.
2. Vercel 프로젝트 → **Storage → Create Database → Upstash (Redis)** 를 만들어 프로젝트에 연결합니다. 접속 정보(`KV_REST_API_URL`, `KV_REST_API_TOKEN` 또는 `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`)가 환경변수로 자동 등록됩니다.
3. 다시 배포합니다 (Deployments → 최근 배포 → Redeploy, 또는 새로 푸시).

빌드 명령과 경로 설정은 `vercel.json`에 들어 있어 따로 입력할 필요가 없습니다.

- Redis 환경변수가 없으면 메모리에만 저장해서 동작은 하지만 데이터가 수시로 초기화됩니다.
- Vercel에는 계속 도는 타이머가 없어서, 새 ERP 전표는 화면이 상태를 물어볼 때(몇 초 간격) 확인합니다.
- 데이터를 처음 상태로 되돌리려면 Upstash 콘솔에서 `hbm:db` 키를 지웁니다. 다음 접속 때 새로 만들어집니다.
- 로컬 `npm start`는 지금처럼 `data/db.json` 파일을 씁니다.

## 데모 순서

0. **로그인**: 사번(숫자 4~10자리), 이름, 비밀번호(4자 이상)를 넣고, 다음 화면에서 그룹과 팀을 고릅니다. 데모라서 형식만 확인하고 비밀번호는 저장하지 않습니다. 실제 사내 비밀번호는 넣지 마세요. 왼쪽 아래 "로그아웃"으로 처음 화면에 돌아갑니다.
1. **첫 화면**: 우리 부서가 최근 간 곳, 타부서 평점이 좋은 곳, 지금 시기에 자주 간 곳, 단체 사진이 많이 올라온 곳, 아무 부서도 안 가 본 새로운 곳이 카드로 보입니다. 카드 아래에 추천 이유가 한 줄로 붙고, 화살표로 좌우로 넘깁니다.
2. **새 활동 기획**: 조건을 넣고 조직도에서 부서원을 고른 뒤 "에이전트에게 날짜 추천받기"를 누릅니다.
3. **날짜**: 중요한 과제 일정과 겹치는 기간은 후보에서 자동으로 빠집니다. 후보를 여러 개 골라 "투표 메일 보내기"를 누릅니다. "데모: 부서원 3명 응답 받기"를 누르거나, 미응답자 화면 링크로 직접 투표하면 결과가 실시간으로 바뀝니다. "이 날로 확정"을 누릅니다.
4. **장소**: 추천 근거(이맘때 우리 부서·타부서 경비 기록, 후기, 단체 사진, 날씨)를 펼쳐 보고 "이곳으로 확정하고 안내 메일 보내기"를 누릅니다. 아래 "완전히 새로운 제안"에서 고를 수도 있습니다. 확정하면 후기 폼을 발송할지 묻습니다.
5. **예약**: "예약하기"를 누르면 네이버 지도가 새 탭으로 열립니다.
6. **ERP 등록**: "활동 후 ERP에 경비 등록"을 누르면 가상 ERP 등록 화면이 계획 내용으로 채워져 열립니다. 등록합니다.
7. **자동 기록**: 10초 안에 에이전트가 전표를 감지합니다. 기획 화면이 "기록" 단계로 바뀌고, 메일함에 기록 업데이트 메일이 옵니다. 기록에 코멘트를 남깁니다.
8. **후기**: 4번에서 "네"를 골랐다면 기록이 올라올 때 후기 폼이 발송됩니다. 메일함에서 받는 사람을 부서원으로 바꿔 후기 요청 메일의 폼을 작성하면 평점이 기록과 추천에 반영됩니다.

오른쪽 위 "에이전트 로그"에서 에이전트가 한 일을 순서대로 볼 수 있습니다.

## 알아 둘 점

- 장소 이름은 가상이므로 예약 버튼은 "지역 + 업종"으로 네이버 지도 검색을 엽니다.
- 후기 폼은 네이버 폼을 대신하는 데모 화면입니다.
- 날씨 예보와 사내 블로그·동아리 단체 사진도 가상 데이터입니다.
- 캘린더와 과제 일정은 서버를 처음 실행한 날짜 기준으로 생성됩니다. 날짜가 많이 지나면 `npm run reset`으로 다시 만드세요.
